# Telegram-магазин с WebApp: бот + FastAPI + React

**Русский** | [English](README.en.md)

Готовый магазин внутри Telegram: клиент открывает меню прямо в чате с ботом, собирает корзину, выбирает доставку или самовывоз и оплачивает заказ. Менеджеры получают заказы в свою группу и подтверждают их одной кнопкой, а владелец получает отчёты по выручке.

В репозитории демо-кофейня «Зерно» с двумя точками. Название, точки, меню и категории меняются в двух файлах — см. [Как адаптировать под свой магазин](#как-адаптировать-под-свой-магазин).

## Возможности

**Для клиента**
- меню в Telegram WebApp: категории, варианты товара (объём, вкус), поиск, наличие в реальном времени;
- выбор способа получения: самовывоз из одной из точек (у каждой свой склад) или доставка;
- расчёт стоимости доставки по адресу: геокодер Яндекса + расстояние по дорогам через свой OSRM;
- оформление заказа целиком в приложении: телефон запоминается, адрес, оплата наличными или по СБП;
- квиз «Подобрать напиток» с добавлением результата сразу в корзину;
- акции на всё меню через переменные окружения.

**Для менеджеров**
- заказ приходит в группу менеджеров с кнопками «Заказ отдан» / «Отменить»;
- склад резервируется в момент заказа и возвращается при отмене или через 24 часа без подтверждения;
- управление наличием (+1 / −1) с телефона прямо в WebApp.

**Для владельца**
- отчёты за день, неделю, месяц и квартал по каждой точке: наличные, карта с учётом эквайринга, доставка, сервисный сбор;
- расчёт ЗП менеджеров по ставке за каждую выданную позицию;
- автоматический отчёт за прошедший день в 00:00 и ежедневный бэкап базы в Telegram;
- рассылка всем клиентам с предпросмотром и подтверждением;
- доступ к магазину только для подписчиков канала (опционально).

**Безопасность**
- цены, остатки и суммы пересчитываются на сервере, клиенту доверяются только id товара и количество;
- каждый запрос WebApp подписан: проверка HMAC `initData` Telegram с ограничением срока жизни или подписанной ботом ссылки;
- админ-эндпоинты принимают только свежий `initData` от ID из `ADMINS_ID`;
- списание склада «всё или ничего» в одной транзакции, защита от дублей позиций и от заказа товара из чужой точки;
- WebApp не открывается в обычном браузере, API без подписи отвечает 403, порт приложения наружу закрыт, HTTPS через Caddy.

## Стек

| Часть | Технологии |
|---|---|
| Бот | Python 3.11, aiogram 3 (long polling, FSM) |
| API | FastAPI, Pydantic, aiosqlite (SQLite) |
| Фоновые задачи | APScheduler |
| WebApp | React 19, TypeScript, Vite, Tailwind CSS 4, motion |
| Доставка | Яндекс Геокодер, OSRM (OpenStreetMap), geopy |
| Инфраструктура | Docker Compose (multi-stage build), Caddy |

## Архитектура

```
Telegram ──► бот (aiogram) ─┐
                            ├─ один процесс main.py ──► SQLite (shop.db)
WebApp (React) ──► FastAPI ─┘         │
                                      ├──► Яндекс Геокодер (адрес → координаты)
                                      └──► OSRM (расстояние по дорогам)
```

Бот и API работают в одном процессе и делят один объект `Bot`: API сам отправляет заказы в группу менеджеров. FastAPI отдаёт и JSON API, и собранный WebApp, поэтому API работает на том же домене и CORS не нужен.

| Файл | За что отвечает |
|---|---|
| `main.py` | точка входа: БД, uvicorn, планировщик, polling бота |
| `server_api.py` | REST API для WebApp, проверка подписей, акции, раздача статики |
| `handlers/routes.py` | бот: `/start`, FAQ, заказы для менеджеров, `/admin`, рассылка |
| `handlers/shop_dp.py` | схема БД, склад, отчёты, демо-меню |
| `handlers/delivery.py` | стоимость доставки |
| `handlers/cron.py` | отчёт за день, бэкап БД, истечение неподтверждённых заказов |
| `handlers/subscription.py` | проверка подписки на канал |
| `webapp/src/shop.ts` | название, точки, часы работы, категории |
| `webapp/src/App.tsx` | меню и корзина |
| `webapp/src/components/` | оформление, оплата, квиз, управление наличием |

## Быстрый старт

### Локально

```bash
cp .env.example .env            # заполните BOT_TOKEN, WEBAPP_URL, MANAGER_CHAT_ID, ADMINS_ID, SHOP_COORD
pip install -r requirements.txt
cd webapp && npm ci && npm run build && cd ..
python main.py                  # бот + API на :8000, при первом запуске БД заполняется демо-меню
```

Telegram открывает WebApp только по HTTPS. Для локальной проверки пробросьте порт 8000 через туннель (например, `cloudflared tunnel --url http://localhost:8000`) и укажите полученный адрес в `WEBAPP_URL`.

Разработка фронтенда с hot reload: `cd webapp && npm run dev`. Vite запускается на :3000 и проксирует `/api` на :8000. Проверка типов: `npm run lint`.

### На сервере (Docker + Caddy)

```bash
git clone <repo> /opt/shop && cd /opt/shop
cp .env.example .env && nano .env
touch shop.db                   # иначе Docker создаст вместо файла каталог
bash osrm/prepare.sh            # карта города для расчёта доставки, один раз
docker compose up --build -d
```

`/etc/caddy/Caddyfile`:

```
shop.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

OSRM необязателен. Без него расстояние считается как прямая × 1.4, и оформление заказа работает. Город для карты задаётся переменными `REGION_URL` и `BBOX` в `osrm/prepare.sh`.

## Как адаптировать под свой магазин

1. **Точки:** `LOCATION_NAMES` и `DELIVERY_LOCATION` в `handlers/shop_dp.py`, те же ключи — в `PICKUP_POINTS` и `DELIVERY_POINT` в `webapp/src/shop.ts`.
2. **Категории:** `CATEGORIES` в `shop.ts`, ставки ЗП менеджеров — `MANAGER_PAY_PER_UNIT` в `shop_dp.py`, картинки — `webapp/public/img/`.
3. **Меню:** `DEMO_MENU` в `shop_dp.py` загружается только в пустую базу. Дальше наличие ведётся из WebApp.
4. **Название, контакты, оплата, акции, город:** `.env` (см. `.env.example`).
